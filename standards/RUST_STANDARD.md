# Rust engineering standard — v0.1

MUST = mandatory when applicable; CONDITIONAL = required when trigger applies. Exceptions require owner, rationale, alternative control, expiry and independent approval. A missing check is BLOCKED, not PASS. Official language semantics supersede local guidance; safety/security and human-approved project constraints remain authoritative.

| ID | Domain | Level | Requirement | Source IDs | Acceptance evidence |
|---|---|---|---|---|---|
| RB01 | Ownership and memory | MUST | Prefer safe Rust; model ownership explicitly, borrow instead of cloning unless ownership or measured performance warrants it; no leaking resources for convenience. | S01,S02,R01 | Review lifetime/ownership boundaries and resource-drop tests. |
| RB02 | Unsafe and FFI | MUST | Isolate unsafe in narrow reviewed modules; document every unsafe operation's safety invariant, provenance, alignment, initialization, aliasing, ABI and lifetime as applicable. Enable unsafe_op_in_unsafe_fn lint; forbid unsafe in safe-only crates. Never introduce unsafe solely to appease borrow checker. | S01,S03,S04,S05,R01 | Inventory unsafe incl. generated/native code; reviewer checks invariants; Miri on compatible tests plus native boundary tests. |
| RB03 | Errors and panics | MUST | Return Result for recoverable failures, Option for absence; propagate with context; no unchecked unwrap/expect/indexing on untrusted input or routine I/O. Justified invariant assertions and tests are permitted. | S07,R03 | Negative tests: malformed input, missing data, overflow, I/O failures; review panic paths. |
| RB04 | Types and API | MUST | Use domain types/enums for invalid-state prevention, explicit units, bounded input, documented public API and minimal visibility; preserve semver contracts. | S01,R02 | API review and doc tests; boundary tests. |
| RB05 | Concurrency and async | MUST | Define lock order, bounded queues, backpressure, cancellation and shutdown. Avoid holding locks across await unless justified; isolate blocking work from async executors and surface task failures. | S02,S07 | Timeout, cancellation, saturation, ordering and shutdown tests; model-check sensitive interleavings where feasible. |
| RB06 | Formatting and lints | MUST | Use rustfmt and Clippy; new warnings fail CI. Suppress individual lints only with reason/scope; do not blanket enable pedantic or suppress all warnings. | R06,R09 | cargo fmt --all -- --check; cargo clippy for supported targets/features with -D warnings. |
| RB07 | Correctness tests | MUST | Write unit, integration, regression and doc tests as applicable, including edge cases; use property tests for invariants and fuzz untrusted parsers. Reproduce each fixed bug before/with fix. | S02,S05,S07,R05,R08 | Record commands, seeds, input corpus, outcomes; tests run on intended feature matrix. |
| RB08 | Unsafe dynamic checks | CONDITIONAL | Run pinned-nightly Miri on compatible unsafe/FFI wrapper tests; native sanitizers or hardware tests where Miri cannot execute; do not treat either as proof. | S04,S05,S06,R01 | Miri logs or BLOCKED with alternative and review; no false N/A. |
| RB09 | Cargo and reproducibility | MUST | Declare edition and supported rust-version; pin tested toolchain for release; commit lockfile for applications and CI reproducibility, test dependency resolution for libraries where needed; minimize enabled features. | R04,R05 | Locked builds/tests; MSRV test where claimed; record rustc -Vv and cargo -V. |
| RB10 | Dependencies and supply chain | MUST | Review direct/transitive crates, unsafe and native dependencies, build scripts/proc macros, licenses and advisory findings; avoid unexplained new runtime dependencies. Never run untrusted code with secrets. | S03,S05,R07 | cargo tree, cargo audit, license/provenance review; unresolved material risk blocks release. |
| RB11 | Performance | MUST | Establish workload, baseline and budget before optimization; measure release builds on equivalent hardware/input; avoid speculative unsafe, allocations or clones; report distributions and regressions. | S04,R02 | Record benchmark commands, toolchain, hardware, repetitions and uncertainty; no universal speed claims. |
| RB12 | Portability | MUST | Declare supported OS/architectures and feature combinations; isolate platform bindings and native dependencies; validate runtime on supported targets, not merely cross-compile. | R04,R05 | Mac/Linux target matrix and actual runtime evidence; mark unavailable target BLOCKED. |
| RB13 | Observability and data protection | MUST | Use structured logs, error context and bounded telemetry without secrets, personal data or unbounded payloads; validate external inputs and apply least privilege. | S07,R03,R07 | Redaction, limit, malformed input and failure-path tests; security review. |
| RB14 | Release and evidence | MUST | Independent review for material changes; record commit, policy SHA, commands, target, tests, artifacts/digests, findings and approvals; no claims based solely on compilation. | R05,R06,R07 | Release dossier and PASS/FAIL/BLOCKED per applicable gate; human approval for production. |
| RB15 | Real-time and numerical profiles | CONDITIONAL | For audio/SDR callbacks avoid blocking, allocation and unbounded work; measure overruns and latency. For scientific code specify units, overflow, NaN/Inf, tolerances and reference results. | S02,S07,R02 | Native device/latency tests or numerical reference fixtures; hardware-dependent claims blocked until observed. |
